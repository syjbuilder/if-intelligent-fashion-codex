I.F V0 TRD 사전 질문사항
=========================

이 파일은 I.F V0 TRD 작성을 시작하기 전에 필요한 의사결정을 정리하기 위한 질문지입니다.
각 질문 아래의 "답변:" 줄에 직접 내용을 적어주세요.
모르는 항목은 "추천 필요", "아직 미정", "나중에 결정"처럼 적어도 됩니다.


1. 개발 방향
------------

1-1. V0는 우선 웹 MVP로 시작하는 것이 확정인가요?
답변: 우선은 웹 MVP 

1-2. 모바일은 반응형 웹까지만 할까요, 아니면 처음부터 모바일 사용성을 거의 앱처럼 잡을까요?
답변: 너의 의견을 듣고싶어


1-3. 앱 전환은 나중에 React Native/Expo 쪽을 염두에 둘까요, 아니면 우선 웹만 만들고 앱 래퍼를 검토할까요?
답변: 너의 의견을 듣고싶어


2. 기술 스택
------------

2-1. 선호하는 프론트엔드가 있나요? 예: Next.js, React, Vite
답변: next.js

2-2. 백엔드는 따로 둘까요, 아니면 Next.js 안의 API route/server action으로 시작할까요?
답변: fastapi(이거에 대한 너의 의견)

2-3. DB는 선호가 있나요? 예: PostgreSQL, Supabase, Firebase, MySQL
답변: supabase

2-4. 1인 개발/바이브코딩 기준으로 최대한 쉬운 조합을 원하나요, 아니면 확장성을 더 중시하나요?
답변: 확장성


3. 로그인 / 계정
----------------

3-1. V0에서 Google, Kakao, Naver 로그인을 모두 구현할까요?
답변: 모두 구현

3-2. 아니면 Google만 먼저 하고 Kakao/Naver는 다음 단계로 둘까요?
답변: 모두 구현	

3-3. 로그인 없이 랜딩과 데모 결과 미리보기는 가능하게 할까요?
답변: 가능하게 응


4. AI 기능
----------

4-1. V0에서 AI 룩 이미지는 실제로 매번 생성할까요, 아니면 데모/초기 프롬프트는 사전 생성 이미지로 시작할까요?
답변: 데모/초기 프롬프트는 사전 생성 이미지로 (너의추천도 듣고싶어)

4-2. 이미지 생성 모델은 특정 후보가 있나요? 예: OpenAI 이미지 모델, Midjourney 수동 생성, Stable Diffusion 계열
답변: nanobanana, open ai 이미지 모델

4-3. 프롬프트 해석은 LLM으로 자동 분석할까요, 아니면 처음엔 규칙/태그 기반으로 단순하게 갈까요?
답변: 내가 생각하는 방향은 llm인데, 너의생각은?


5. 상품 / 룩 DB
---------------

5-1. curated look DB 500개는 직접 사람이 선별해서 입력하는 방식으로 갈까요?
답변: 응

5-2. 상품 링크는 처음에 수동 입력인가요, 아니면 일부 쇼핑몰에서 크롤링/API 연동을 고려하나요?
답변: 일부 쇼핑몰에서 크롤링/api 연동을  고려(너의 의견 필요)

5-3. 운영자용 어드민은 V0에 꼭 필요할까요, 아니면 처음엔 CSV/스프레드시트로 관리해도 될까요?
답변: 어드민 필요


6. 결제 / 토큰
--------------

6-1. V0에서 실제 결제를 붙일까요?
답변: 결제붙일것

6-2. 아니면 토큰/플랜 구조만 DB에 설계하고 결제는 나중에 붙일까요?
답변: 설계 + 결제 (너의의견필요)

6-3. 무료 사용자는 몇 회 정도 생성/저장할 수 있게 생각하고 있나요?
답변: 3회 (너의의견필요)


7. 저장 / 공개
--------------

7-1. 사용자가 생성한 룩 저장은 V0 필수인가요?
답변: V0 필수는 아닌데 있으면 좋음 (너의 의견필요)

7-2. 공개/비공개 설정도 V0에 바로 넣을까요?
답변: 난이도에 따라서 너의 의견 필요

7-3. 공개 룩 탐색 피드는 V0에서는 제외하는 것으로 유지할까요?
답변: 응


8. 개발 범위
------------

8-1. V0에서 꼭 있어야 하는 화면은 어디까지인가요?

예:
- 랜딩
- 로그인
- 메인 프롬프트 화면
- AI 룩 결과
- 상품 패널
- 저장/히스토리
- 토큰/플랜
- 어드민

답변:
랜딩, 로그인, 결제(토큰/플랜), 어드민, 상품패널, AI룩 결과, 메인프롬프트 화면, 저장히스토리

8-2. 실제 개발 전에 디자인 시안이 먼저 필요할까요, 아니면 TRD를 먼저 잡고 디자인으로 넘어갈까요?
답변: 디자인은 별도로 진행 중 (병행예정)


9. 운영 / 배포
--------------

9-1. 배포는 어디를 생각하고 있나요? 예: Vercel, Netlify, AWS, Supabase
답변: vercel, supabase (근데 너의 의견 및 조언이 필요)

9-2. 도메인은 이미 정했나요?
답변: 너의 의견 및 조언 필요(잘모르는분야)

9-3. staging 환경도 처음부터 둘까요?
답변:너의 의견 및 조언 필요(잘모르는분야)


10. 먼저 답하면 좋은 핵심 질문
------------------------------

아래 7개 질문은 TRD 초안을 잡기 위해 특히 중요합니다.
위 질문에 모두 답하기 어렵다면, 이 7개부터 먼저 답해주세요.

10-1. Next.js + Supabase 같은 쉬운 웹 MVP 조합으로 가도 되는가?
답변: 가능

10-2. 앱 전환은 React Native/Expo 가능성을 열어두는 정도면 되는가?
답변: 너의 의견 및 조언 필요(잘모르는분야)

10-3. 로그인은 Google부터 시작할지, Kakao/Naver도 V0에 포함할지?
답변: 모두 포함

10-4. AI 이미지는 실시간 생성인지, 사전 생성/검수 룩도 섞을지?
답변: 원래 의도는 실시간 생성(너의 의견 및 조언 필요(잘모르는분야))

10-5. curated look DB는 어드민으로 관리할지, 스프레드시트로 시작할지?
답변: 어드민으로 관리

10-6. V0에서 실제 결제를 붙일지, 토큰 구조만 설계할지?
답변: 토근 구조 설계 + 결제 

10-7. V0 필수 화면 범위는 어디까지인지?
답변: 8-1 답변 참고
