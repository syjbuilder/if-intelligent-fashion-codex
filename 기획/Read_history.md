## 1. 프로젝트 개요

프로젝트명:

```text
I.F.
```

I.F.의 의미:

- I am Fashion
- IF, 가능성
- Intelligent Fashion

핵심 메시지:

```text
Wear what you imagine.
If you can imagine, you can wear it.
```

I.F.는 사용자가 텍스트 프롬프트로 상상한 패션 스타일을 AI 룩 이미지로 시각화하고, 그 룩과 유사하거나 어울리는 실제 구매 가능한 국내 패션 상품으로 연결하는 AI 패션 탐색 서비스다.

I.F.는 자사몰이 아니다. 직접 상품을 판매하거나 자체 결제/배송/환불을 담당하는 서비스가 아니라, 여러 온라인몰과 브랜드에 흩어진 상품을 사용자의 프롬프트와 연결하는 독립형 AI 커머스 탐색 레이어다.

## 2. 처음 논의한 문제의식

초기 질문은 SEO가 아니라 AI 검색 최적화, GEO/AEO/LLMO 관점에서 의류 브랜드나 상품이 LLM에 어떻게 잘 연결될 수 있는지였다.

예시로 "캐주얼한 요가복"을 AI에게 입력했을 때 특정 브랜드나 상품이 추천되려면 어떻게 해야 하는지가 논의되었다.

이후 방향이 바뀌었다. 사용자는 특정 브랜드를 AI 검색에 노출시키려는 것이 아니라, 프롬프트 기반으로 패션 이미지를 생성하고, 그 이미지 또는 사용자의 의도를 실제 판매 상품과 연결하는 중간 플랫폼을 만들고자 했다.

초기 컨셉:

```text
프롬프트 → AI 패션 이미지 생성 → 유사 실제 상품 매칭 → 판매 사이트 연결
```

이 서비스는 Pinterest, Midjourney, ChatGPT, 쇼핑 검색을 결합한 형태에 가깝다고 정리되었다.

## 3. 참고한 해외/국내 레퍼런스

초기 레퍼런스로 다음 서비스들이 논의되었다.

### Daydream

- 자연어 기반 AI 쇼핑/패션 검색 에이전트
- 상황별 착장 질문에 답하고 브랜드 상품을 추천
- 미국/유럽 브랜드 중심
- I.F.와의 차이: I.F.는 한국 여성 패션, 한국어 상황 표현, 국내 브랜드/쇼핑몰 연결에 집중

### Doji

- 셀피 기반 AI 아바타/가상 피팅 서비스
- I.F.와의 차이: I.F.의 V0는 가상 피팅이 아니라 텍스트 프롬프트 기반 룩 생성과 상품 연결

### OneOff

- 셀럽/크리에이터 룩 기반 쇼핑 큐레이션
- I.F.와의 차이: I.F.는 셀럽 이름 기반 생성이 아니라, 사용자가 업로드한 사진 속 의류를 분석해 동일/유사 상품을 찾는 방향으로 확장 예정

### LookSync

- AI 생성 룩과 실제 카탈로그 상품을 매칭하는 연구/프로토타입
- I.F.의 기술 파이프라인 레퍼런스로 참고

### ZIGZAG 직잭렌즈

- 사진 촬영 또는 업로드 기반 유사 상품 검색
- 지그재그 앱 안에서 판매 중인 동일/유사 상품 추천
- I.F.와의 차이:
  - 지그재그는 사진 기반 검색이 중심
  - I.F.는 텍스트 프롬프트 기반 상상/탐색이 중심
  - 지그재그는 앱 내부 상품 추천
  - I.F.는 여러 브랜드/쇼핑몰을 가로지르는 독립형 탐색 레이어

### Zara

- Zara 앱의 이미지 검색 및 AI Virtual Try-On 레퍼런스가 논의됨
- Zara는 자사 상품을 사용자에게 입혀보는 브랜드 내부 기능
- I.F.는 사용자가 먼저 프롬프트로 상상한 스타일을 입력하고, 여러 브랜드/쇼핑몰 상품으로 연결하는 서비스

## 4. 서비스 철학

I.F.는 단순히 AI 기술 자체를 보여주는 서비스가 아니다.

사용자는 AI 서비스의 가치를 두 축으로 보았다.

1. 기술 자체의 발전
2. 기술 발전을 통해 사람들의 삶에 실질적 가치를 더하는 것

I.F.는 두 번째 축에 집중한다.

모든 기술 발전이 삶을 편하게 만드는 것은 아니다. 키오스크나 온라인 주문 시스템은 효율을 높였지만, 시니어에게는 오히려 주문과 소비를 더 어렵게 만들 수 있다.

I.F.는 AI를 기술 시연이 아니라 생활 문제 해결 도구로 사용한다. 특히 온라인 의류 쇼핑의 정보 과잉, 선택 피로, 검색어 표현의 어려움, 접근성 문제를 줄이는 것이 목표다.

장기적으로는 20-30대 여성뿐 아니라 시니어와 디지털 쇼핑에 익숙하지 않은 사용자까지도 온라인 의류몰에 쉽게 접근할 수 있도록 돕는 서비스로 확장하고자 한다.

## 5. 핵심 포지션

I.F.의 핵심 포지션:

```text
프롬프트 기반 AI 패션 탐색 서비스
```

정의:

```text
사용자가 상상한 스타일을 말로 입력하면,
AI가 그 스타일을 시각화하고,
여러 국내 패션 쇼핑몰/브랜드 중 실제 구매 가능한 선택지로 연결해주는 독립형 AI 패션 탐색 레이어.
```

피해야 할 포지션:

- 지그재그 렌즈의 다른 버전
- 무신사/에이블리 상품 추천 챗봇
- AI로 예쁜 옷 이미지만 만들어주는 앱
- 가상 피팅 앱
- 자사몰

## 6. V0 핵심 결정사항

### 6.1 입력 방식

V0의 메인 입력은 텍스트 프롬프트다.

이미지 업로드는 V0의 핵심 기능이 아니라, 결제 단계 또는 유료 플랜에서 확장되는 추가 기능으로 본다.

예시 프롬프트:

- 여름 데이트에 입을 꾸안꾸 룩
- 키 162cm, 하체 커버되는 출근룩
- 제니 사복처럼 미니멀한 블랙 데일리룩이지만 부담스럽지 않게
- 한강 피크닉에 어울리는 사진 잘 나오는 룩

### 6.2 결과 방식

V0의 핵심 결과물은 AI가 생성한 1-3개의 패션 룩 이미지다.

AI 이미지의 역할은 중간 보조 자료가 아니라, 사용자가 처음 마주하는 핵심 결과물에 가깝다.

다만 완벽한 전신 화보보다 다음을 우선한다.

- 옷이 잘 보일 것
- 상황과 배경이 있을 것
- 모델과 무드가 표현될 것
- 실제 상품 매칭이 가능할 것

### 6.3 상품 추천 방식

추천 단위는 개별 상품이 아니라 전체 룩이다.

사용자가 전체 룩 이미지를 클릭하면:

- 메인 추천 상품 조합
- 개별 아이템별 상품
- 유사 상품
- 관련/어울리는 상품
- 외부 구매 링크

가 표시된다.

자체 결제는 V0에서 하지 않는다. 외부 쇼핑몰/브랜드 페이지로 이동한다.

### 6.4 상품 DB

V0는 전체 룩 기준 500개 curated look DB로 시작한다.

전체 쇼핑몰을 자동 크롤링하거나 API 연동하기 전에, 사람이 선별한 룩 데이터셋으로 핵심 경험을 검증한다.

룩 데이터에는 다음이 포함된다.

- 프롬프트
- AI 생성 이미지
- 시즌
- 상황
- 무드
- 색상
- 핏
- 구성 아이템
- 실제 구매 링크
- 유사 상품 링크
- 공개/비공개 활용 가능 여부

### 6.5 카테고리

초기 범위:

- 20-30대 여성 의류
- 상의
- 하의
- 원피스
- 아우터

제외:

- 신발
- 가방
- 액세서리
- 속옷
- 수영복
- 화장품

### 6.6 플랫폼

V0는 데스크톱 우선 반응형 웹이다.

우선순위:

1. 데스크톱 웹
2. 모바일 웹

데스크톱 구조:

- 왼쪽: 사이드바
- 중앙: 프롬프트 입력, AI 룩 결과
- 오른쪽: 룩 클릭 시 상품 패널

모바일 구조:

- 상단: 로고, 메뉴, 계정/토큰
- 중앙: 프롬프트 입력과 AI 룩 결과
- 상품 패널: 바텀시트
- 히스토리/저장: 메뉴 또는 별도 탭

### 6.7 로그인

로그인이 있어야 데모 프롬프트 및 생성 기능을 사용할 수 있다.

지원 예정 로그인:

- Google
- Kakao
- Naver

국내 서비스 활성화를 위해 Kakao/Naver 로그인을 고려한다.

### 6.8 데모 프롬프트

로그인 후 데모 프롬프트 1회를 제공한다.

데모 프롬프트는 계절별/검색량 기반으로 주기적으로 바꾼다.

예:

- 4월: 벚꽃 데이트룩, 봄 하객룩
- 6월: 여름 데이트룩, 장마철 출근룩
- 9월: 가을 캠퍼스룩, 환절기 데일리룩
- 12월: 연말 모임룩, 겨울 데이트룩

### 6.9 저장/공개/커뮤니티

사용자는 생성된 룩, 프롬프트, 추천 상품 결과를 저장할 수 있다.

기본값은 비공개 저장이다.

사용자가 공개 저장을 선택하면 향후 서비스 내 탐색/커뮤니티 영역에 노출될 수 있다.

장기적으로 GitHub나 21st.dev처럼 다른 사용자의 결과를 참고하고 탐색하는 공간을 만들 계획이 있다.

## 7. 결제/수익모델 방향

월구독 + 토큰 모델을 고려한다.

무료:

- 제한된 프롬프트 검색
- 제한된 이미지 생성
- 기본 상품 추천
- 제한된 저장 개수

유료:

- 더 많은 생성 횟수
- 더 많은 저장 공간
- 고급 필터
- 이미지 업로드 검색
- 인플루언서/연예인 룩 유사 상품 검색
- 내 얼굴 합성/개인화 모델
- 히스토리 기반 개인화 추천

V0에서는 자체 결제를 통한 상품 구매는 하지 않는다.

## 8. 기술 전략 요약

초기부터 이미지 생성 모델을 파인튜닝하는 것보다, 상품 데이터 구조화가 먼저다.

핵심 원칙:

```text
모델 파인튜닝보다 상품 데이터 구조화와 프롬프트-상품 매칭 데이터 자산 구축이 먼저다.
```

해야 할 작업:

- 상품 이미지 캡셔닝
- 색상/핏/소재/무드/상황/계절 태그 구조화
- 상품 이미지에서 역프롬프트 추출
- 한국어 상황형 프롬프트 사전 구축
- 프롬프트와 상품 매칭 평가
- 사용자 클릭/저장/구매 링크 클릭 데이터 수집

모호한 프롬프트 처리:

```text
"여름철 남친룩"
→ 계절: 여름
→ 무드: 깔끔함, 데일리, 호감형
→ 아이템 후보: 린넨 셔츠, 반팔 니트, 와이드 슬랙스 등
```

활용 가능한 데이터:

- 네이버 데이터랩
- Google Trends
- YouTube 검색 결과
- Pinterest Trends
- 네이버/구글 검색 결과
- I.F. 내부 클릭/저장 데이터

## 10. ADR 논의

개발자 친구가 ADR을 작성했는지 물었다.

ADR은 Architectural Decision Record의 약자다.

의미:

```text
왜 이 기술/구조/방식을 선택했는지 기록하는 의사결정 문서
```

PRD가 "무엇을 만들지"라면 ADR은 "왜 그렇게 만들기로 했는지"를 기록한다.

초기 ADR 후보:

- ADR-001: V0는 웹 기반 MVP로 시작한다
- ADR-002: V0는 텍스트 프롬프트를 핵심 입력으로 한다
- ADR-003: 초기 상품 데이터는 curated look DB 500개로 시작한다
- ADR-004: V0에서는 자체 결제를 제공하지 않는다
- ADR-005: AI 룩 생성은 하이브리드 방식을 사용한다
- ADR-006: 이미지 업로드와 얼굴 기반 피팅은 V0에서 제외한다
- ADR-007: 공개 저장 결과는 향후 커뮤니티 확장을 고려해 설계한다

ADR은 운영하면서 계속 추가/갱신한다.

기존 ADR을 삭제하기보다 상태를 바꾼다.

- Proposed
- Accepted
- Superseded
- Deprecated

권장 위치:

현재는 기획 폴더 상위에 `ADR` 폴더를 만들어도 된다.

예상 구조:

```text
C:\Users\syj\Desktop\IF\코덱스
├─ 기획
│  ├─ If discovery summary.md
│  ├─ I.F V0 PRD.md
│  └─ 기타 문서
└─ ADR
   ├─ ADR-001-web-mvp.md
   ├─ ADR-002-prompt-first-input.md
   └─ ADR-003-curated-look-db.md
```

개발 repo가 생기면 보통 `docs/adr/`에 둔다.

## 12. 새 환경에서 이어가는 방법

컴퓨터를 바꾼 후에는 다음 문장을 Codex에게 말하면 된다.

```text
이 폴더의 Read_history.md, If discovery summary.md, I.F V0 PRD.md를 읽고 I.F 프로젝트를 이어가줘.
```

대화가 길어져서 맥락이 흐려질 때도 동일하게 파일 기준으로 다시 이어가면 된다.

중요한 원칙:

- 대화를 기억에만 의존하지 말고 MD 파일을 기준 문서로 사용한다.
- 새 의사결정이 생기면 PRD, Discovery, ADR 중 맞는 문서에 반영한다.
- 기술 구현 상세는 PRD가 아니라 TRD에 분리한다.
